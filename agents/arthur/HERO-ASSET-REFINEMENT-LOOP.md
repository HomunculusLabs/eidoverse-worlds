## CAROUSEL HERO CAMPAIGN

Judge in this order, always from current pixels rather than this prose:

1. gameplay-distance silhouette and instant carousel identity;
2. crown/canopy hierarchy: apex, roof pitch, valance/eave rhythm, underside;
3. horse quality: unmistakable horse anatomy, distinct carved poses, pole and
   suspension logic, saddle/bridle/trapping readability, phased bob silhouette;
4. platform/fascia/ticket-entry storytelling and construction coherence;
5. value/material hierarchy: festive cream/red/gold/wood without noisy detail;
6. night identity: warm interior glow, readable horses/deck, crown as village
   beacon rather than bulbs floating over a black mass;
7. motion pair, rider socket alignment, approach/readability, and grounding.

The baseline review's first evidenced target is the crown: the current straight,
dark eave and nearly dead apex make the gameplay silhouette read too much like a
gazebo. Re-check current pixels before editing; if still true, make ONE coherent
crown/canopy intervention first. Source truth outranks a vision model: decode any
claimed mechanical defect against `mkcarousel.ts` before accepting it.

### One visual iteration

1. Preserve baseline images and baseline full hash in a tick-specific review dir
   under `agents/arthur/reviews/hero-assets/<tag>-<subject>/before/`.
2. Inspect at minimum front/right/back/left, gameplay distance, aerial, night,
   and two motion phases. Use the available image-analysis tool for a second eye,
   but Arthur owns the judgment. Compare against the immediately previous
   accepted hash, not a vague memory.
3. Name ONE highest-value defect with pixel evidence. Trace it to source.
4. Make the smallest source change that repairs the whole visible defect class.
   Keep statics merged and motion/socket/light anchors named. Healthy target:
   5–45 nodes unless an explicit visual benefit justifies a narrowly documented
   exception; never spend draw calls on invisible micro-detail.
5. Rebuild twice. Require byte-identical full SHA-256 outputs. Run GLB/deep audit:
   dimensions, node/draw count, materials/textures, named anchors, degenerate and
   NaN geometry, floating clusters, collider posture, and rider clearances.
6. Render the candidate into the tick's `after/` directory with identical views,
   lighting, camera, and motion phases. Make a side-by-side/contact sheet.
7. Falsify the change: check silhouette, horse readability, construction logic,
   back/side completeness, night read, camera occlusion, and whether detail
   survives at gameplay distance. If it is not clearly better, revert only this
   tick's owned source edit and record the rejected hypothesis. A reverted
   experiment is valid progress; never place it.
8. If clearly better, update the durable plan with before/after hashes, one-line
   visual verdict, evidence paths, and next highest-value defect.
